# Production delivery

The `Portfolio validation` workflow validates push and pull request changes on the repository-scoped `jeremy-portfolio-isolated` runner. Only a push to `main` packages the validated production build and hands it to the separate `jeremy-portfolio-publisher` runner. The publisher runs after the `production` environment's required approval. Pull requests, development pushes, and manual validation do not deploy.

Before deployment, the publisher verifies the artifact checksum and source SHA, confirms the production Worker, account and domains, checks the GitHub environment's owner-review and main-only restrictions, checks the `PRODUCTION_DELIVERY_ENABLED` environment variable and rollout expiry, and verifies that the approved SHA is still `main`. The deployment command consumes the validated bundle; it does not rebuild the application. The `productionDelivery` flag fails closed and expires on 2026-12-07 unless replaced or removed after review.

The `production` GitHub environment needs a `CLOUDFLARE_API_TOKEN` environment secret. Create an account-owned token scoped to the existing `jeremy-portfolio-production` Worker, with only the permissions needed for the Worker and its existing custom domains; store it directly in GitHub, never in the repository or logs. Verify its permissions before considering delivery operational. Missing credentials or publisher capacity must fail or queue rather than falling back to hosted runners.

The legacy Cloudflare Workers Builds connection for `jeremydevv` was set to `auto_build_enabled: false` and `previews_enabled: false`; its trigger definitions remain for recovery. GitHub Actions is the intended deployment authority. The production Worker and routes were not changed by this migration. Before restoring any legacy trigger, review its production-approval and runner implications.

Locally, run `npm run check:production`, `node --test scripts/verify-production-bundle.test.mjs scripts/check-production-environment.test.mjs`, and `node scripts/verify-production-bundle.mjs`. A dry run can inspect the generated bundle with `npx wrangler deploy --config dist/jeremy_portfolio_development/wrangler.json --dry-run`. These checks do not deploy or prove a live production rollout.
